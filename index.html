Typography

A Fluid Type Scale

Every type size scales fluidly between viewport breakpoints using pure-CSS clamp(). You define only the min and max sizes as tokens, and the preferred value (the slope) is computed live with tan(atan2()) — so overriding a size token recomputes automatically, with no hand-tuned magic numbers to maintain. Body text, badges, and buttons have their own independent scales.

It relies only on widely-supported CSS (clamp(), the vi viewport unit, and trigonometric functions), so it works in every current browser with no JavaScript and no polyfill.

The framework uses a special class .page-content for the wrapper with actual content. Why it matters? Because we reset default browser's styling, like margin for paragraphs etc. Yet we keep consistent spacing for content specific elements inside an element with class .page-content.

Getting Started with BCSS

Installation & Setup

Include the framework stylesheet in your HTML <head>. No build tools, no package managers — just a single CSS file that does the heavy lifting. The framework is designed to work out of the box with sensible defaults while remaining completely customizable through CSS custom properties.

Customizing Your Theme

Override --color--primary--original on the :root to shift the entire primary palette. Every shade from 50 to 950 recalculates automatically via CSS relative color syntax — no Sass, no PostCSS, no preprocessor required.

BCSS was built on the premise that a good CSS framework should accelerate your work, not constrain it. Sensible defaults with full escape hatches.

Working with Dark Mode

Dark mode is handled automatically via prefers-color-scheme: dark. You can also force a specific theme by setting the data-theme-default attribute on the <html> element — useful for user preference overrides.

Support

Frequently Asked Questions

How do I install BCSS?

BCSS is a single CSS file with no build step required. Download framework.css and include it in your HTML <head>. For Builderius users, the framework is already included in the standard starter, no actions is needed. That's it — no npm, no webpack, no configuration files.

Can I customize the primary color?

Yes — update the --color--primary--original CSS custom property on :root (or any parent element). All 11 primary shades (50 through 950) are computed automatically using CSS relative color syntax and the OKLCH color space. Use the live color picker in the Customize panel on this page to preview changes in real time.

Does BCSS work without Builderius?

Absolutely. BCSS is a plain CSS file that works in any web project. The builderius-menu-builder.css companion file is the only Builderius-specific piece — everything else (framework.css) is framework-agnostic and works with vanilla HTML, WordPress, or any other CMS.

How does the dark mode system work?

BCSS listens to prefers-color-scheme: dark and remaps all color shades — so --color--primary--100 becomes the darkest shade and --color--primary--950 becomes the lightest. You can override this by setting data-theme-default="light" or data-theme-default="dark" on the <html> element, which is exactly what the theme switcher in the Customize panel does.

How do I contribute to BCSS?

Open an issue or pull request on the GitHub repository. Before submitting, check the existing issues to avoid duplicates. New component proposals should include a working HTML/CSS example. For bug reports, include a minimal reproduction case with the affected browser and OS version.
